## Клавиатура на Android — главная открытая тема

Под клавиатуру страницу могут ужимать три механизма, и на каждой прошивке работает своя комбинация: система ужимает окно, Chrome ужимает `visualViewport`, либо не срабатывает ни то, ни другое. Вдобавок Chrome на vivo **панорамирует** viewport (`offsetTop`).

Текущая логика (`sux-chat-app/src/main.tsx` + нативный `InsetsPlugin`):

- плагин отдаёт `ime` (перекрытие клавиатуры с WebView) и `webH` (высоту WebView);
- `сдвиг = max(0, vv.height − (webH − ime))`, результат пишется в `--kb-height`;
- ненулевой сдвиг применяется только после того, как viewport сдвинулся от значения, зафиксированного на `keyboardWillShow`, либо через ~840 мс. Нулевой применяется сразу (сборка 262);
- `--vv-top` = `visualViewport.offsetTop` ставится **синхронно** в scroll/resize визуального viewport и сдвигает `#root` (сборка 263);
- при открытой клавиатуре резерв под полосу навигации обнуляется (было лишних 118 px);
- `interactive-widget=resizes-content` в meta viewport стоит, но WebView на Redmi его игнорирует.

Что известно:

- **Redmi, 263**: замер через DOM, 5 открытий подряд — визуальный низ панели 518–519 = кромка клавиатуры, `vvTop` 0 → 173 компенсируется.
- **Запись экрана Redmi на 263** (`adb screenrecord`, раскадровка) разобрана не до конца. В нескольких кадрах во время анимации открытия панель стоит выше кромки клавиатуры (≈40–95 px устройства, порядка 100–150 мс). Непонятно, это остаточный прыжок или клавиатура просто ещё выезжает. Отчёт субагента по раскадровке оказался недостоверным: он утверждал, что кадры одинаковые или чёрные.
- **vivo** (тестировщик SuperSasha, экран 436×949 @2.475): жаловался, что панель «подпрыгивает на ещё одну высоту клавиатуры и возвращается». Правки 262 и 263 делались под это, но **на vivo 263 ещё не проверена**. Его последний лог был со сборки 250, до всех правок.

Следующий шаг: попросить с vivo баг-репорт на 263 (открыть чат, тапнуть в поле 2–3 раза, затем «Сообщить о проблеме»). В строках `kb show` и `kb …` есть `vv0`, `vvTop`, `webH` — по ним видно, в какой момент применился сдвиг. На Redmi при желании повторить запись экрана и посчитать кадры заново.

## Как выкладывать

- **Номер сборки** = `git rev-list --count HEAD`. Пишется в `nginx/apk-page/version.json` в том же коммите, который этот номер получит.
- **Коммиты без `Co-Authored-By: Claude`** — просьба пользователя.
- **Бэкенд**: код на сервере примонтирован томом. `ssh` на 194.164.245.144 (проект в `/home/home-restored/home/hyax`), `git pull`, миграции гоняются при старте, затем перезапустить контейнер `api`.
- **Веб**: `npm run build` в `sux-chat-app`, залить в `hyax/web` на сервере, сверить sha256 бандла на выдаче.
- **APK**: `npx cap sync android`, затем `./gradlew assembleDebug` (подпись debug, совпадает с витриной). Если сборка висит без вывода — это осиротевший gradle-демон: `kill -9` и `--no-daemon`. Тулчейн (SDK, gradle-кеш, JDK, Xcode) лежит на внешнем диске `/Volumes/Ext` (`~/extdisk`); без диска ничего не соберётся.
- **Установщики**: положить в `/tmp/hyax-dist` (система его чистит), затем `~/hyax-deploy-s3.sh [файлы]`. Скрипт льёт через boto3 multipart в `hyax-public/installers/` (venv `~/.hyax-venv`, ключ `~/.hyax-s3.env`), потом по ssh делает `git pull` и копирует `index.html`, `version.json`, `studio.html` в `backend/media/apk/`.
- **Ловушки**:
  - `.deb` собирать только на Linux-сервере в контейнере `node:22` с `binutils`;
  - `electron-builder --linux` — всегда с `--x64`;
  - не забывать `.blockmap`;
  - политику на основной бакет `hyax` не ставить: у Yandex политика — единственное правило доступа, она ломает PutObject приложения.
- **iOS → TestFlight**:
  1. Поднять `CURRENT_PROJECT_VERSION` в `ios/App/App.xcodeproj/project.pbxproj` (4 вхождения).
  2. `npm run build && npx cap sync ios`.
  3. `xcodebuild … -configuration Release -destination "generic/platform=iOS" archive -allowProvisioningUpdates`.
  4. `xcodebuild -exportArchive -exportOptionsPlist ios/App/ExportOptions.plist`. Если упало с таймаутом — повторить экспорт из того же архива.
- **Установка на Redmi**: `adb install -r`. MIUI периодически выключает «Установку через USB» (`INSTALL_FAILED_USER_RESTRICTED`) — тогда просить пользователя включить её снова или класть APK в `Download`.

## Как мерить Android (вместо догадок)

- В `capacitor.config.ts` включён `webContentsDebuggingEnabled`.
- Найти сокет: `adb shell cat /proc/net/unix | grep -o "webview_devtools_remote_[0-9]*"`.
- Пробросить: `adb forward tcp:9333 localabstract:<сокет>`, адрес websocket взять из `curl http://127.0.0.1:9333/json`.
- Дальше `Runtime.evaluate` через node + `ws` (`NODE_PATH=~/project/hyax/sux-chat-app/node_modules`). Полезно читать `innerHeight`, `visualViewport.height/offsetTop`, `--kb-height`, `--vv-top`, `getBoundingClientRect()` панели ввода.
- Тапы: `adb shell input tap X Y` (CSS-координаты × `devicePixelRatio`). Закрыть клавиатуру — `input keyevent 4`.
- Журнал вибраций: `adb shell dumpsys vibrator_manager`.
- Запись экрана: `adb shell screenrecord`, раскадровка через ffmpeg (без `drawtext`), числа считать через PIL в `~/.hyax-venv`.
- Картинки в основной сессии не открываются (глобальный хук) — смотреть их субагентом `image-reader` и перепроверять его цифры.
