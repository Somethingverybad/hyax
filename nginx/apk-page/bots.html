Как устроено

Бот в WhoYaX — обычный аккаунт с пометкой «бот». У него есть профиль, ник, аватар и личка; люди находят его по ссылке https://huyax.e-tree.su/u/<ник>, пишут в личку или добавляют в группы. Бот ходит в то же REST API, что и приложение, а события получает через тот же личный WebSocket. Всё, что умеет приложение, умеет и бот — просто без экрана.

  1. Создайте бота — от своего аккаунта, один запрос. В ответе токен: покажется один раз, храните его как пароль. 
    POST https://huyax.e-tree.su/api/bots/
Authorization: Bearer <ваш JWT>

{"username": "mybot", "bio": "Что умеет бот"}

→ 201 {"bot": {"id": "…", "username": "mybot", "token": "Xy…"}}
  2. Подключитесь к сокету и слушайте события (ниже).
  3. Отвечайте обычными сообщениями: текст, файл, кнопки под сообщением.

Свои боты: GET /api/bots/ (с токенами). Перевыпустить токен: POST /api/bots/<id>/. Удалить: DELETE /api/bots/<id>/.

Авторизация

Каждый запрос — с заголовком Authorization: Bot <token> (или X-Bot-Token: <token>). В WebSocket токен передаётся параметром ?token=.

GET /api/profiles/current/
Authorization: Bot Xy…

→ {"id": "<bot_id>", "username": "mybot", "is_bot": true, …}

Свой id нужен для адреса сокета — возьмите его отсюда при старте.

События: личный сокет

Адрес: wss://huyax.e-tree.su/ws/user/<bot_id>/?token=<token>. Сообщения — JSON вида {"type": "notification", "data": {…}}; смотрите на data.type:

data.typeКогдаПоля
new_messageНовое сообщение в любом чате бота (личка, группа, канал, где он админ) chat_id, message — объект сообщения: id, content, sender {id, username}, file_url, file_name, reply_to…
buttonНажали кнопку под сообщением бота chat_id, message_id, data (строка кнопки), from_id, from_username
inline_queryЧеловек набрал @mybot запрос в любом чате query_id, query, chat_id, from_id, from_username
inline_chosenЧеловек выбрал один из ваших inline-результатов query_id, result_id, chat_id, message_id — заглушка, которую нужно заполнить
Свои сообщения тоже приходят в сокет — отсекайте по message.sender.id == bot_id. Сокет может рваться: переподключайтесь с паузой, а пропущенное подтягивайте GET /api/messages/sync/?chat=<id>&since=<ISO>.

Отправка

Текст

POST /api/messages/
{"chat": "<chat_id>", "content": "Привет!"}

Файл

Сначала загрузка, потом сообщение с адресом файла. Картинки покажутся картинкой, mp3 — плеером, mp4 — видео, остальное — файлом.

POST /api/upload/          multipart/form-data, поле file
→ {"file_url": "s3://…", …}

POST /api/messages/
{"chat": "<chat_id>", "content": "", "file_url": "s3://…", "file_name": "track.mp3",
 "file_width": 1280, "file_height": 720}          размеры — для видео и картинок

Ответ на сообщение

{"chat": "<chat_id>", "content": "Вот", "reply_to_id": "<message_id>"}

Писать бот может туда, где он участник: в свою личку с человеком, в группу, куда его добавили, в канал, где он админ. Личку с человеком создаёт человек — бот сам никому не пишет первым.

Кнопки под сообщением

Ставить кнопки может только бот. buttons — ряды кнопок; в каждой text (подпись) и data (до 128 символов, вернётся вам событием button). Нажатие в историю не пишется — вы сами решаете, что ответить.

{"chat": "<chat_id>", "content": "Что скачать?",
 "buttons": [[{"text": "🎵 MP3", "data": "dl|mp3|k1"}],
             [{"text": "720p", "data": "dl|720|k1"}, {"text": "1080p", "data": "dl|1080|k1"}]]}
Не кладите в data ссылки и секреты: держите у себя словарь «короткий ключ → значение», как в примере.

Inline-режим

Человек пишет @mybot запрос в любом чате — не обязательно в личке с ботом. Через полсекунды после последнего символа приложение шлёт запрос, вам приходит inline_query. Вы отвечаете списком, он появляется над полем ввода; человек тапает строку — в чат от его имени уходит сообщение с подписью «через @mybot», а вам приходит inline_chosen с message_id. Заполните это сообщение содержимым.

  1. Получили inline_query → ответьте списком (до 20 строк). Ответ должен быть быстрым: приложение ждёт до 12 секунд, поэтому inline годится для поиска и подсказок, а тяжёлую работу делайте после выбора. 
    POST /api/bots/inline/<query_id>/answer/
{"results": [
  {"id": "mp3|k1", "title": "Linkin Park — Numb", "description": "MP3 · 3:07 · Linkin Park",
   "thumb_url": "https://i.ytimg.com/vi/kXYiU_JCYtU/mqdefault.jpg"},
  {"id": "mp3|k2", "title": "…", "description": "…"}
]}
    Поле
    idдо 64 символов, вернётся в inline_chosen
    titleдо 120 символов, обязательно
    descriptionдо 200 символов, вторая строка
    thumb_urlhttps-картинка для превью, необязательно

    Пустой список — приложение покажет «Ничего не нашлось».

  2. Получили inline_chosen → в чате уже висит заглушка «⏳ <title>» от имени человека. Подготовьте содержимое и заполните её — текстом, файлом или обоими. На это есть 30 минут. 
    POST /api/bots/inline/messages/<message_id>/
{"content": "", "file_url": "s3://…", "file_name": "Numb.mp3"}

или, если не вышло:
{"content": "Не получилось: видео недоступно"}

    Поля те же, что у обычного сообщения: content, file_url, file_name, file_width, file_height, video_url, voice_url. Не переданный content станет пустым.

Разбор запроса — ваше дело. У @ytbot первое слово — формат (mp3, 1080, 720, 480, 360), остальное — название или ссылка; без формата — mp3. Придумывайте свой синтаксис, но описывайте его в «О себе» бота.

Пример: минимальный бот на Python

Эхо в личке, одна кнопка и inline-поиск по своему списку. Нужен только aiohttp.

import asyncio, json, os, aiohttp

API = "https://huyax.e-tree.su/api"
WS  = "wss://huyax.e-tree.su/ws"
TOKEN = os.environ["BOT_TOKEN"]
H = {"Authorization": f"Bot {TOKEN}"}
ITEMS = {"1": "Первый ответ", "2": "Второй ответ"}

async def main():
    async with aiohttp.ClientSession() as s:
        me = await (await s.get(f"{API}/profiles/current/", headers=H)).json()
        async with s.ws_connect(f"{WS}/user/{me['id']}/?token={TOKEN}", heartbeat=30) as ws:
            async for raw in ws:
                d = json.loads(raw.data).get("data") or {}
                t = d.get("type")
                if t == "new_message" and d["message"]["sender"]["id"] != me["id"]:
                    await s.post(f"{API}/messages/", headers=H, json={
                        "chat": d["chat_id"], "content": f"Вы написали: {d['message'].get('content') or '…'}",
                        "buttons": [[{"text": "Ещё раз", "data": "again"}]]})
                elif t == "button":
                    await s.post(f"{API}/messages/", headers=H, json={"chat": d["chat_id"], "content": "И снова здравствуйте"})
                elif t == "inline_query":
                    q = d["query"].lower()
                    res = [{"id": k, "title": v} for k, v in ITEMS.items() if q in v.lower()]
                    await s.post(f"{API}/bots/inline/{d['query_id']}/answer/", headers=H, json={"results": res})
                elif t == "inline_chosen":
                    await s.post(f"{API}/bots/inline/messages/{d['message_id']}/", headers=H,
                                 json={"content": ITEMS.get(d["result_id"], "?")})

asyncio.run(main())

Полный рабочий бот с загрузкой файлов — bots/media-bot в репозитории (это и есть @ytbot).

Ограничения и правила

Кнопкиdata ≤ 128 символов; ставит только бот
Inline-результаты≤ 20 строк; id ≤ 64, title ≤ 120, description ≤ 200 символов; запрос живёт 10 минут
Заполнение заглушки30 минут после выбора; только своя заглушка
Куда писатьТолько в чаты, где бот участник; первым в личку не пишет
ФайлыЛимита на размер нет, но большие файлы грузите одним запросом рядом с сервером или кусками
Спам, рассылки без согласия и подмена чужих сообщений — повод отключить бота. Пишите в «О себе», что бот делает и как им пользоваться.
