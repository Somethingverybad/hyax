# media-bot — ссылка в чат, файл в ответ

Бот качает видео и музыку по ссылке (yt-dlp) и кладёт файл в чат.

## Устройство

```
core/download.py      ядро: yt-dlp, выбор качества, ffprobe — общее для всех
transports/hyax.py    бот хуякса: личный сокет + REST, авторизация токеном бота
```

Транспорт отвечает только за «откуда пришла ссылка и куда положить файл».
Правка в ядре чинит всех ботов сразу — телеграмный бот (`yt-tg-bot`) может
импортировать тот же `core/`.

**Чего здесь нет и не нужно:** всего слоя с «живым аккаунтом» и MTProto, на
котором держится телеграмная версия. Он существует только ради обхода лимита
Telegram в 50 МБ для ботов; у хуякса сервер свой, и файл уходит обычной
загрузкой.

## Настройка

1. Создать бота (от имени владельца, в приложении или запросом):
   `POST /api/bots/ {"username": "ytbot"}` → в ответе `token`.
2. Переменные окружения:

```
HYAX_BOT_TOKEN=<токен из ответа>
HYAX_API=http://api:8000/api     # внутри docker-compose
HYAX_WS=ws://api:8000/ws
HYAX_QUALITY=720                 # 360 | 480 | 720 | 1080
HYAX_PARALLEL=2                  # сколько ссылок качать разом
COOKIES_DIR=/cookies             # необязательно: youtube.txt и т.п.
```

3. `docker compose up -d media-bot`

## Как пользоваться

Написать боту в личку (или добавить в группу) ссылку — придёт файл.
`/audio <ссылка>` — только звук mp3. `/video <ссылка>` — видео. `/help` — справка.

## Куки

Без кук YouTube отдаёт не всё. Положите `youtube.txt` в формате Netscape в
`COOKIES_DIR` — ядро подхватит их по площадке ссылки.
