# Ретро-ПК на сервере

Windows 98 крутится не в браузере, а на сервере в QEMU/KVM; в мини-приложение
WYX идёт только экран (VNC через WebSocket), обратно — касания и клавиши.
Для чего: совместные «Герои III» по сети. У каждого игрока своя машина, машины
одной комнаты объединены локальной сетью (мультикаст-сокет QEMU, без root и TAP).
Телефон ничего не эмулирует, партия не рвётся, когда у кого-то погас экран:
машина живёт на сервере, игрок просто переподключается.

Сервер — crystal (NL): KVM, 6 ядер, ~6 ГБ свободной памяти. Одна машина —
128 МБ ОЗУ + ~60 МБ QEMU. Веб-доступ — через `milf.hyax.ru/retro-cloud/`
(nginx `vpn-web`, блок добавляет владелец под root).

## Как устроено

```
data/base/win98.img     общий образ (raw), только чтение — тот же, что в bots/retro, плюс
                        выключенное ускорение мыши и без окна приветствия
data/base/heroes3.iso   диск в приводе у всех
data/disks/<uid>.qcow2  диск игрока: тонкая копия поверх базы, тут его сохранения;
                        снимок «idle» — усыплённая машина, следующий вход продолжает с него
data/run/               сокеты VNC и QMP машин
data/allow.txt          кому можно: @username или id, по строке (как в bots/retro)
```

Протокол WebSocket `/ws` описан в `server/index.js`. Ввод идёт не через VNC,
а через QMP `input-send-event`: мышь PS/2 относительная, положение курсора сервер
считает сам (`server/vm.js`): «парковка» в угол даёт известную точку, дальше шаги
≤100 px, в образе ускорение указателя выключено (Mouse → Motion → Slow), иначе
шаг больше порога удваивается. Одно событие PS/2 несёт не больше 127 px.

Грабли Windows 98 в QEMU: с `-cpu` с APIC она виснет на логотипе (гасит LAPIC);
пересканирование PnP и таймер монитора выключают VBE у драйвера VMDisp9x — экран
превращается в полосы, лечится записью `0x1ce/0x1cf` (index 4 → 0x41) или
перезагрузкой. Сетевая карта PCI не находится, пока в системе нет «PCI bus»
(`pci.vxd` из cab-файлов Windows 98 SE).

## Сеть в образе (с 07.11.2026)

В базе `data/base/win98.img` стоят «PCI bus» (`pci.vxd`, `pcimp.pci`), карта
Realtek RTL8029 (`-device ne2k_pci`), TCP/IP без клиента сетей Microsoft (иначе
запрос пароля при входе). DHCP в комнате нет — Windows берёт APIPA-адрес
169.254.x.x сама (ждёт ~60 с при холодном старте, поэтому первая загрузка ≈3 мин).
Машины одной комнаты видят друг друга: ping проходит, в Heroes III → Multiplayer →
TCP/IP показывается свой адрес, HOST создаёт партию; второй игрок жмёт JOIN и
вводит адрес хоста (он виден у хоста в этом же окне). Кабинеты русской 98 SE лежат
в `C:\WINDOWS\OPTIONS\CABS` (SourcePath в реестре), поддержка кириллицы и
раскладка «Russian» установлены, но переключение Alt+Shift из эмулятора пока не
срабатывает — известная недоделка.

Пересборка базы: в DEV-экземпляре довести машину, выключить Windows изнутри
(Пуск → Завершение работы), `/dev/hmp/<uid>?cmd=quit`, остановить оба контейнера,
`qemu-img convert -f qcow2 -O raw disks/<uid>.qcow2 base/win98.new.img` в образе
`retro-qemu` с теми же монтированиями, подменить `win98.img`, удалить все
`disks/*.qcow2` и `run/*` (оверлеи ссылаются на старую базу), запустить контейнеры.

## Запуск на crystal

```
~/retro-cloud/app      — эта папка (rsync из репозитория), data → ../data
cd ~/retro-cloud/app && docker compose up -d --build
curl http://127.0.0.1:8099/health
```

`.env`: `HYAX_BOT_TOKEN` (токен @heroesIII, им подписаны данные запуска),
`DEV=1` — без проверки допуска, страница `/dev/` и `/dev/init?id=…` для проверки
без WYX. Проверка протокола без браузера: `node test/client.mjs http://127.0.0.1:8099 1001 "" move:640,512 click:left`.
